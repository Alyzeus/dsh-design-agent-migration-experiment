## 3. 六个关键问题

### Q1 · 能否独立完成从设计需求到最终交付的完整闭环？

**不能。当前是「半自动可交付」，不是「全自动闭环」。**

- 链路本身能跑：需求冻结 → 布局合同 → 校验 → Photoshop 排版 → PSD/PNG → 客观闸门 → 外部评审。
- 四个断点：素材生成后端当前不可用；缺主体必须停下来问用户；终稿必须人工签收；没有单一编排入口。
- 没有一单同时满足「真实素材 + 评审通过 + 人工签收」：两个终稿案例都被外部审查判「会被拦下」。

### Q2 · 导演层是真的在参与创意决策，还是仍在做提示词与工具调度？

**真实参与了一次「提案 + 路由」，但没有承担「裁决 + 止损 + 重构」。**

- 有实质内容：两套方向、5 维差异、选择建议与理由、制作分工、失败预案，且方向真实驱动了后续排版合同。
- 不足：最终选择由人做出；系统建议被否；批准后的改动由用户指令驱动；没有二次裁决，也没有「换方向」的实例。
- 结论：不是「只会提示词」，但也不是「自主导演」；现在的角色是**提案者与路由建议者**。

### Q3 · 招式库能否影响实际创作，并在新任务中得到验证？

**能影响创作；「在新任务中验证有效」尚未证明。**

- 有引用证据：多个项目把招式写进 Brief 与布局合同的 `style_refs`，并落到具体字段。
- 没有对照证据：没有「用库 vs 不用库」的 A/B，没有跨会话/跨模型迁移测试，没有盲评。
- 组字实验证明的是排版规则可量化（重心、墨距），不是「招式让作品更好」。

### Q4 · Qwen、ComfyUI、Photoshop 之间是否实现有效分工，还是仍需要大量人工？

**分工清晰，落地是「排版/校验/审查自动化较高，素材与决策仍重度人工」。**

| 角色 | 实际做什么 | 人工仍要做什么 |
|---|---|---|
| Qwen | 视觉审查、拆解卡批处理 | 批准付费调用；解释评审结论 |
| ComfyUI | 生图（历史记录完整：模型、seed、日志） | 写主体提示词、选候选图；当前还要先启动服务 |
| Photoshop | 排版执行（布局合同 → 可编辑 PSD） | 修字体/替换商品图、终稿签收 |
| DeepSeek | 主控、状态、编排、写需求与方向文件 | 决策与验收 |

### Q5 · Critique 与 Design Loop 能否发现问题、完成修订并在失败时回滚？

**能发现、能改；回滚目前不成立。**

- 发现：闸门抓过字号过小、墨高不足、边距误判；外部视觉审查 10 次，问题带坐标；独立评审把自评 83.4 打到 69.0；校验器的 9 类注入错误全被抓。
- 修订：七轮 76→86 的曲线可追溯；五版试跑每次只改 1–2 项；四轮外部问题 6→4。
- 拒绝：有过「撤回评审误判」和「不改、只改口径」的真实案例。
- 回滚：回滚命令在当前环境直接报权限错误，没有一次真实演练；只有手工回退案例。

### Q6 · 与升级前相比，哪些提升有真实作品或测试数据支持？

**工程能力有数据；作品质量没有对照数据。**

| 提升 | 支持数据 |
|---|---|
| 可编辑排版 | 最新试跑稿 14 层 / 12 个文字层；重开复核字号、字距与合同一致；单稿 36–67 秒 |
| 布局合同与校验 | 12 个文字块 / 0 错误；9 类注入错误全部被抓 |
| 语料与招式 | 158 图（155 可参考）/ 158 卡 / 46 招；检索工具实测命中 |
| 组字判据 | 横排重心 8.3–12.5px → 0.4–0.6px；墨距 CV 13–36% → 0；5% 字面率阈值被证伪 |
| 视觉审查 | 10 次真实记录；一次 3 条素材级问题；四轮问题数 6→4 |
| 导演层 | 两方向 + 5 维差异 + 路由 + 失败预案（只有形式证据，无质量增益数据） |

## 4. 已具备、可直接使用的能力

1. **结构化排版合同**：文字块含角色、坐标、字体栈、理由、验收条件；合同可校验、可复跑。
2. **Photoshop 自动排版**：一条命令产出可编辑 PSD + PNG；重开可复核字体、字号、字距。
3. **客观闸门**：9 项几何/字号/对比/占位符检查可复跑，输出逐项结果。
4. **校验器负向能力**：越界、溢出、重叠、对比度、缺解释、缺验收、非法对齐、幽灵引用、招式不存在，9 类注入错误全部被抓。
5. **外部视觉审查通道**：10 次历史调用，输出带坐标、四类分流与一句话结论；输入只含需求与成品图，不含作者评分。
6. **语料拆解批处理**：13 张结构化拆解卡成功生成，失败清单为空。
7. **招式影响创作**：招式被写进需求与布局合同，并被校验器核对存在性。
8. **定向返工与止损**：七轮评分曲线、变差回滚、到轮次上限明写「会被拦下」，都有记录。
9. **拒绝无依据意见**：有撤回评审误判、保留原生效果的实例。
10. **语料检索与状态探针**：按桶/标签/图像特征检索；能判断新会话是否继承了完整工作区记忆。
11. **导演层最小试运行**：两套实质不同方向、5 维差异、制作分工、失败预案、人工批准记录。

## 5. 未达成与关键风险

### 5.1 未实现（13 项）

- 第三方生图 API 接入；统一任务契约；后端能力表；同题双后端对比。
- 行距（多行排版）；主体保护区/图文避让；CMYK/出血印刷输出。
- 招式失败案例；跨任务风格迁移验证。
- 策略级重构（换方向）；导演层 A/B 对照；单一编排入口。
- 错字检测。

### 5.2 四个关键个案（匿名）

| 个案 | 事实 | 说明 |
|---|---|---|
| **A · 闸门与验收标准脱节** | 一次真实稿闸门 9/9 通过，但日期墨高实测 **10.6%**，冻结标准要求 **18%** | 闸门只在清单里带「硬指标」时才校验墨高；清单没带，就跳过了。这是「假通过」，已列为 P0 |
| **B · 对齐语义未落位** | 一个右对齐文字块，合同框右缘与画布右边距对齐，实测墨迹右缘比框右缘短 **154px**；三个同组标签的右缘分别为 969/947/947 | 点文字的对齐只影响行内 justification，不会把整块贴到框右缘；回读的 `dx/dy=0` 掩盖了这一点 |
| **C · 回滚不可执行** | 回滚命令在 `dry-run` 下就报系统权限错误；没有一次真实回滚演练 | 规则写了「变差能回退」，能力没有落地；目前只有手工回退 |
| **D · 审查可审计性不足** | 外部审查记录不绑定产物哈希；同一路径的文件被后续版本覆盖后，无法逐轮证明「看的是哪一版」 | 评审结论可信，但追溯链不完整 |

### 5.3 风险与影响

| 风险 | 影响 | 当前处置 |
|---|---|---|
| 闸门通过 ≠ 满足验收标准 | 可能把不合规稿当合格交付 | P0：清单必带硬指标，缺字段即失败 |
| 对齐/行距/保护区未实现 | 「精确排版」仍靠人眼兜底 | P0/P1：实现锚点语义与行距，或从合同删除 |
| 回滚不可执行 | 变差版本退不回去 | P0：修回滚、做演练、留回退记录 |
| 双后端只有一条 | 无法按任务选后端，也无法证明分工代价 | P1：先出能力表，再做一类同题对比 |
| 独立评审不稳定 | 自评偏高时缺少第二意见 | P1：固定外部审查 + 人工抽检 |
| 审查不绑哈希 | 评审与产物对不上号 | P1：审查输出写产物哈希 |

## 6. 统计口径（可复算）

### 6.1 分母与状态

- **分母：62 项**，由 10 个模块拆出的可判定子能力组成，逐项列在附录 A；每项只计一次。
- 状态定义：
  - **已验证**：本轮或历史上有可复查产物/实跑记录。
  - **部分实现**：能力存在但覆盖不全，或有已知硬缺陷。
  - **已实现但尚未验证**：代码/数据在，但从未在实际任务中使用。
  - **仅完成设计文档**：只有文字/字段定义，没有执行路径。
  - **未实现**：没有代码、没有产物。
- 计算：
  - 已实现（含部分）= 26 + 21 + 1 = **48 / 62 = 77.4%**
  - 已验证 = **26 / 62 = 41.9%**
  - 已实现项中真正验证过的比例 = 26 / 48 = **54.2%**
  - 未实现 = **13 / 62 = 21.0%**
- 整体完成度不取单一伪精确值：下界「只算已验证」41.9%，上界「已验证 + 部分 + 已实现未验证」77.4%，**区间中点 59.7%**。

### 6.2 七项完成标准

| # | 标准 | 判定 |
|---|---|---|
| 1 | 确认真实能力与限制，保留可用路径 | 部分 |
| 2 | 至少一个同题双后端对比，或说明哪路未运行 | 部分 |
| 3 | 能从测试记录选后端并解释分工/代价 | **未达成** |
| 4 | 有可打开的可编辑 PSD 与真实预览 | **达成** |
| 5 | 能拒绝硬错、拒绝无据建议、回退变差版本 | 部分 |
| 6 | 经验有来源、适用条件、失败反例 | 部分 |
| 7 | 状态/日志/成本可恢复，封包未被覆盖 | 部分 |

**1 项达成 / 5 项部分 / 1 项未达成。**

### 6.3 证据分级

| 级别 | 含义 |
|---|---|
| **A** | 本轮亲自执行命令或重开产物，结果可复现 |
| **B** | 有落盘文件、时间戳、参数记录，本轮未复跑（付费/环境不允许） |
| **C** | 只在文档/回复里声称，无产物或日志；不计为通过 |

> 本文把 A、B 计为「已验证」；C 只作背景。没有运行证据的设计方案，不因「写得完整」而算迁移成功。

## 7. 下一阶段改进路线

### P0 · 阻断性（不修不能宣称闭环）

1. **验收标准接入闸门**：清单必须携带硬指标（如墨高占比），缺字段即失败。
2. **修回滚链**：回滚命令在可写路径执行；`dry-run` 不落盘；完成一次真实回滚演练。
3. **修跨会话恢复**：恢复脚本指向正确的工作区根，并适配不同项目的状态文件。
4. **对齐、行距、保护区逐项落地**：每项要么实现，要么从合同删除，不允许「写了不实现」。

### P1 · 能力补齐

5. **后端能力表**：逐项写清可用/不可用与原因；再做一类同题对比（各 1–2 张）。
6. **分布对照进评审**：每次评审附「被评图指纹 vs 语料分位数」，越界必须给理由。
7. **三型验收进模板**：Brief / System / Craft 分栏，加导演级创意核查。
8. **招式经验卡**：补适用条件、失败反例、迁移状态；做一次新题材迁移测试。

### P2 · 工程化

9. **单一编排入口**：把初始化 → 合同 → 校验 → PS → 闸门 → 评审 → 检查点串起来。
10. **统一清单 schema**：排版适配器与闸门共用一份清单，去掉手工转换。
11. **版本封包与文档同步**：当前版本重新封包，包说明与版本号对齐；脚本去掉硬编码路径。
12. **成本记录**：每次付费调用写费用（未知写 `unknown`）。

## 8. 这份报告的边界

**它能证明：**

- 哪些能力有可复查产物、哪些只是文档；
- 工程链路能跑到哪一步、断在哪；
- 各模块的验证率与整体完成度区间；
- 主要风险与下一步优先级。

**它不能证明：**

- 作品「更好看」或「达到人类设计师水平」——没有人工盲评；
- 导演层带来了质量增益——没有同引擎的「有/无导演层」对照；
- 哪条生图后端更合适——没有同题对比；
- 系统可以无人值守全自动交付——闭环仍有人工签收与素材依赖；
- 任何合规、版权、商用授权结论——未做法律审查。

**样本边界**：单机、单环境；评分含自评；独立评审样本少；部分结论只支持工程判断，不支持统计意义上的排名。

## 附录 B · 术语

| 术语 | 含义 |
|---|---|
| 需求冻结（G1） | 需求、文案、尺寸、风格约束被用户确认，未确认不开工 |
| 客观闸门 | 脚本执行的几何/字号/对比/占位符检查，不过不谈审美 |
| 布局合同 | 每个文字块的角色、坐标、字号、字体、理由与验收条件 |
| 可编辑 PSD | 文字仍是文字层、可改字号字距，不是一张拼合图 |
| 招式库 | 从参考图拆出的可复用做法（M 编号），每条对应可落到参数的动作 |
| 三型验收 | Brief（需求/文案）/ System（规范/招式）/ Craft（画面/工艺）分开评 |
| 导演层 | 负责创意方向、方案取舍、制作路由与止损的决策层 |
| 双后端 | 两条生图路线（第三方 API 与本地 ComfyUI），本报告只一条可用 |
| 统一生图任务契约 | 把「生成什么」与「用哪个后端」分开描述的任务约定 |
| 策略重构 | 局部修补无效时，提案换方向并请人批准，而不是继续调参数 |
| A/B 对照 | 同题、同引擎、只变一个变量的对比实验 |
