# GPT/Codex → DSH 设计 Agent 工作流迁移实验

[English](README.en.md) · [实验复盘](docs/retrospective.md) · [能力矩阵](docs/capability-matrix.md) · [验证计划](docs/validation-plan.md) · [证据与口径](docs/evidence-register.md)

这是一份工作流迁移实验记录，研究如何把 GPT/Codex 侧的设计导演、制作、审图、迭代与经验管理流程，适配到朋友 DSH 的设计 Agent 系统。这里保存实验材料和审计边界，不分发可安装 Agent，也不宣称迁移已全部验收。

**截至 2026-10-27，能够引用的目标端结论是：DSH 对外验收摘要报告“阶段性部分通过”。本次整理实际读取了报告和用户截图，但没有进入 DSH 系统重跑。**

## 当前结论

DSH 报告称：工程执行层迁移成功，导演层完成一次最小试运行；双后端对比、独立验收闭环、经验迁移和可执行回滚尚未达成。报告的 62 项能力统计为：

| DSH 报告状态 | 项数 | 占比 |
|---|---:|---:|
| 已实现且实际验证（包含其本轮实测与历史记录） | 26 | 41.9% |
| 部分实现 | 21 | 33.9% |
| 仅完成设计文档 | 1 | 1.6% |
| 已实现但尚未验证 | 1 | 1.6% |
| 未实现 | 13 | 21.0% |

以上是**报告统计**，不是本仓库维护者亲自复验的 26 项。报告给出的 41.9%–77.4% 是按状态计数的覆盖范围；中点 59.7% 不是实测成功率、质量分或生产就绪度。七项完成标准：1 项达成、5 项部分、1 项未达成。

## 两套系统必须分开

| 维度 | 用户的 GPT/Codex 系统 | 朋友 DSH 的目标系统 |
|---|---|---|
| 主控 | 当前 Codex 会话中的 GPT；配置由宿主决定 | 报告称 DeepSeek 主控 |
| 图像制作 | 本机当前 Visual Director 技能规定使用宿主 OpenAI 原生图像能力 | 保留 **Qwen API + ComfyUI** 两条后端选择目标；两条生图路线未同时落地 |
| Qwen | 不能由 DSH 报告推定本机接入 | 报告称已用于视觉审查与拆解卡；这不等于 Qwen 生图 API 已接入 |
| PS | 原会话用户明确要求 Codex 分支无 PS；当前本机技能也不接桌面修图软件 | 已提供/待核实：报告称已能从合同生成可编辑 PSD；本次未打开 PSD 复验 |
| Layout Planner | 当前本机技能有布局规划与渲染说明；本次只读规则未执行 | 已提供/待核实：报告称有 layout.json 和校验；行距、保护区缺失 |
| 版本关系 | 当前本机技能标注 1.1.1 | 报告对象内部版本 2.3.2；依据升级任务书 v3.0 / Art Director 2.0 |

用户截图里的 **v1.1→v3.0 是该截图的流程版本标记**，不能与本机技能 1.1.1、DSH 内部版本 2.3.2 合并成一条已验证的发布历史。详见[系统边界](docs/system-boundaries.md)。

## 迁移保留的工作流

需求与参考 → Art Director 提案与取舍 → Layout Planner 布局合同 → 后端选择与制作 → PS 排版（目标端）→ Critique → Design Loop → 人工签收 → Style Kit 与长期记忆。

- **Art Director**：表达机制、实质不同方向、取舍理由、工具路由、失败预案。报告只支持一次提案与路由试跑，不支持自主导演或质量增益。
- **双后端**：保留 Qwen API 与 ComfyUI 生图选择；报告只支持 ComfyUI 历史提交/取图，且报告时服务未启动。不能把 Qwen 审图当成第二条生图后端。
- **PS / Layout Planner**：保留已提供的模块及接口意图；报告中的局部实跑证据仍需原始合同、PSD 和回读记录核验。
- **Design Loop / 回滚**：报告称定向返工、拒绝无据意见有记录；程序回滚在 dry-run 阶段报权限错误。手工退回旧稿不能替代机制验收。
- **Style Kit / 长期记忆**：素材检索、招式引用、状态保存不等于跨任务风格迁移有效或跨会话恢复完整。

## 截图所见的关键变化

用户提供的对照表显示：四段变八步；新增三张参考候选与 D0 用户选图；三道闸门变四道；先判匹配度再审细节；循环上限 3→7；规则固定编号共 25 条；语料改按 character/editorial/promo/type 分桶；增加 PS 排版和字形设计；自产图不再作为参考/候选。[完整转录及差异](docs/screenshot-v1.1-v3.0.md)。

截图声称 50 招，而后续报告为 46 招；截图客观闸门 10 项，报告可复跑闸门为 9 项。本仓库保留差异，未用猜测统一数字。

## 如何读证据

1. **本次实际验证**：读取外部报告、查看截图、读取本机源端技能；对报告汇总数字做算术和一致性检查。
2. **对方报告**：目标系统的运行、评分、产物和能力统计，均加“DSH 报告称”。
3. **待核验**：原始日志、PSD、运行环境、逐项证据映射、双后端、自动回滚、跨会话恢复与质量对照实验。

原会话可读返回仅含少量用户消息、助手引用占位符及一张附件，不能据此补写未读到的迁移过程。报告原文见[对外验收摘要](evidence/DSH_DESIGN_AGENT_ACCEPTANCE_EXTERNAL.md)，其中“本轮”“已验证”均指该报告作者的审计口径。
