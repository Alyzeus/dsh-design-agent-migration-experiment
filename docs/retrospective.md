# 实验复盘

## 能支持的判断

现有材料支持一个有限判断：DSH 报告中的工程执行迁移走得比自主设计决策更远。合同、校验、PS 排版与视觉审查有报告所述的实跑记录；创意裁决、双后端选择、经验迁移与自动回滚尚缺完整证据。本次只读取材料，不能替代目标端运行验收。

原会话可读用户消息说明：用户既关心朋友 DSH 的迁移验收，也要求另做一个走 GPT 与 image 模型、无 PS 接入的 Codex 技能。这是两个适配分支。把 DSH 的 DeepSeek/Qwen/ComfyUI/PS 链路描述成用户 Codex 的现有能力，会同时误报两端。

## 迁移中保住了什么

从截图看，工作流把原本隐含的选参考、提问、自检与验收变成显式步骤。这个变化使审美分歧更早出现，并把“方向匹配”放在细节修补前面。它是可见的流程设计变化，尚不能直接推成作品质量收益。

从报告看，layout.json 使文字角色、坐标、字体和验收条件形成可以检查的合同；PS 提供可编辑文字层，而非仅交一张合成图。错误注入和重开回读的报告记录比单纯“脚本执行成功”更有判断价值，但仍应取得原始文件复核。

Art Director 的两套方向与路由建议据报告真实影响了后续合同，说明不只是写长提示词。但最终选择由人承担，也没有策略级换方向实例。因此目前更接近提案者与制作路由建议者。

## 暴露的问题

| 失败模式 | 报告中的具体表现 | 对迁移方法的含义 |
|---|---|---|
| 检查清单脱离有效需求 | 9/9 闸门通过，但日期墨高 10.6%，冻结标准要求 18% | 检查器必须消费同一份硬指标；漏字段应失败 |
| 框对齐掩盖墨迹不对齐 | 一处右缘墨迹距合同框右缘短 154px，dx/dy=0 仍未揭露 | 要验证用户看见的文字位置，不能只读对象属性 |
| 规则存在但执行断裂 | 回滚 dry-run 权限错误，无真实演练 | 文档、命令存在与恢复成功分开验收 |
| 审查结论缺版本绑定 | 同一路径可被下一版覆盖，审查未绑产物哈希 | 保留不可混淆的产物版本引用，必要时哈希 |
| 知识入库等于有效学习 | 招式可检索、可引用，无用库/不用库对照 | 检索命中和风格迁移有效是两项实验 |
| 历史可用等于当前可用 | ComfyUI 有历史记录，报告时未启动 | 报告时间状态和当前探针分栏 |

报告还写出自评 83.4 与独立评审 69.0 的差距。单一例子不能估计总体偏差，但足以说明自评通过不应替代冷读和用户签收。七轮 76→86 也可能同时受评分口径与用户指令影响；没有产物对照和盲评，不能作因果结论。

## 没有得到回答的问题

Qwen API 与 ComfyUI 哪条生图路线更适合什么任务、各自代价多少？导演层是否提高质量？招式在新题材是否有效？长期记忆是否在新会话中恢复准确？这些都需要新增受控试验，当前材料不能回答。

## 下一轮的复盘标准

先修能产生假通过或无法恢复的断点，再补第二生图路线。每项改动都对应一个能失败的测试；一次通过只支持对应环境和样本。作品生成、文件可编辑、设计自评通过、外部评审通过和用户签收分别记录。

这次整理保留报告与截图之间的数字差异，不补造迁移时间线，也不把当前本机技能中的回滚脚本说明用来“修正”目标端失败。这样后续得到新证据时，可以逐项更新结论，而不必推翻一份虚假的完成声明。
